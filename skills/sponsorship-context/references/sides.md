# Organizer vs buyer: what each skill needs

| Skill | Side | Reads from the file |
|---|---|---|
| find-event-sponsors | organizer | event, industry, city, audience |
| price-sponsorship-packages | organizer | tiers, audience, industry, city |
| write-a-sponsorship-prospectus | organizer | audience facts, tiers, dates |
| write-a-sponsor-outreach-email | organizer (or a buyer writing to an organizer) | sender, opt-out line, event facts |
| vet-a-trade-show-before-exhibiting | buyer | domain, competitors, what we sell, budget |
| plan-an-exhibitor-budget | buyer | budget, regions, staff |
| track-competitor-event-spend | buyer | competitor domains, our domain |
| build-an-events-calendar | buyer (or organizer scouting rival events) | industry, regions, months, goal |

## Where the facts come from
- ConferenceDB MCP (`https://conferencedatabase.com/api/mcp`): listings, roles, published package prices, counts.
  Date every number with the read date.
- The user: audience numbers, budgets, goals, past sponsor deals. Never fill these in from the data.
- The event's own website: deadlines, floor plans, exhibitor manuals.
